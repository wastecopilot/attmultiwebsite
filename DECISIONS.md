# DECISIONS

Every judgement call made during the build, with the reason. Newest decisions are appended at the end of each section.

## Project setup

| # | Date | Decision | Reason |
|---|---|---|---|
| D-01 | 2026-10-21 | The git repository root is the workspace folder (it contains `att-site/`, `research/`, `audit/`, `reference/` and the top-level `.md` files). On Vercel, set **Root Directory = `att-site`**. | Keeps the research, audit evidence and decision log versioned next to the code, as the brief asks for an auditable build. |
| D-02 | 2026-10-21 | The 98 MB screen recording, the extracted PNG frames, raw HTML and full-page research screenshots are git-ignored; OCR text, timestamps, JSON and Markdown evidence are committed. | GitHub rejects files over 100 MB and the frames are reproducible from the video with the ffmpeg commands in `research/video-inventory.md`. |
| D-03 | 2026-10-21 | All npm scripts call Node directly (`node node_modules/next/dist/bin/next dev`, etc.) instead of the `next`, `eslint`, `playwright` shims. | The parent folder name contains `&`. npm's Windows `.cmd` shims run `SET dp0=%~dp0` unquoted, so `cmd.exe` splits the path at `&` and the shim fails (observed: `create-next-app` → `next typegen` failed with "Cannot find module C:\Users\pavit\Downloads\next\dist\bin\next"). Calling Node directly works on Windows, macOS, Linux and Vercel. |
| D-04 | 2026-10-21 | Next.js 16.4.2 (current `latest`), React 19.3, Tailwind CSS 4, TypeScript 5, as generated by `create-next-app@16.4.2`. | Latest stable at build time. |
| D-05 | 2026-10-21 | The git remote `origin` is set to `https://github.com/PavithraEbbali/att.git`; commits are made after each milestone, but nothing is pushed by the build process. | The brief asks for commits and names the remote; pushing publishes the code and is left to the owner (`git push -u origin main`). |
| D-07 | 2026-10-21 | `cacheComponents` and `partialPrefetching` (enabled by the create-next-app template) are switched off. Every page is plain statically generated HTML. | The site has no runtime data. Cache Components adds rules (no `Date` during prerender, React `<Activity>` keeping hidden routes mounted) with no benefit for a static marketing site; static generation is simpler to audit and fastest to serve. |
| D-08 | 2026-10-21 | `.env.local` holds clearly labelled **test** values for local development, as requested. Because Next.js loads `.env.local` in production builds too (and it overrides `.env.production`), the production check fails while those test values are present. HANDOVER.md tells the owner to put real values in `.env.production` (or the Vercel dashboard) and not to keep `.env.local` on a machine that builds for production. | Guarantees placeholders can never reach production. |
| D-09 | 2026-10-21 | An **audit build** (`npm run build:audit`, `ALLOW_TEST_ENV=1`) accepts the labelled test values so Lighthouse and the tag tests can run against production-optimised output locally. It writes to `.next-audit/`, shows an "AUDIT BUILD — NOT FOR DEPLOYMENT" badge, and is refused when `VERCEL` or `CI` is set. | Lighthouse must measure a production build, but the real tag IDs and phone number are not available yet. |
| D-06 | 2026-10-21 | Tesseract 5.4.0 installed with `winget install UB-Mannheim.TesseractOCR`; Playwright Chromium installed with `playwright install chromium`. ffmpeg 8.1.1 was already present. | Tools required by Milestone 1. |

## Research

| # | Date | Decision | Reason |
|---|---|---|---|
| D-10 | 2026-10-21 | The reference video is a recording of the retailer's **existing** page (`authorizedinternetretailer.net/att/`, operated by Transtech Marketing Network LLC), not of att.com. It is used for retailer identity (legal name, address, hours, disclosure wording) and as a cross-check of prices; every AT&T price or promo must still match att.com. | Source-of-truth order in the brief: att.com first, video second. |
| D-11 | 2026-10-21 | att.com was fetched with Playwright/Chromium (desktop Chrome user agent, one page at a time, 6 s pause). `robots.txt` (saved at `research/raw/robots.txt`) allows every page used; disallowed paths (`/buy/…`, `/search/`, `/acctmgmt/`, etc.) were not requested. att.com's `ai.txt` permits `ai-input` and forbids `ai-train`; content is used only as input for factual pricing. | Brief: respect robots.txt and rate limits. |
| D-12 | 2026-10-21 | att.com loads "See offer details" fine print only when the button is clicked, so a second Playwright pass (`att-site/scripts/research/offer-details.mjs`) opens each dialog and records its text verbatim. | Brief requires the exact fine print for every promotion. |
| D-13 | 2026-10-21 | `about.att.com` and `www.att.com/accessibility/` returned HTTP 403 to Playwright's headless shell. They were re-fetched with full Chromium (`PW_CHANNEL=chromium`) and returned 200. `/deals/cell-phones/` is a 404; the live phone-deals URL is `/deals/cell-phone-deals/`. | Brief: resolve blocked pages and flag gaps. No gap remained. |
| D-14 | 2026-10-21 | att.com's `llms.txt`, `ai.txt` and `ai-instructions/*.md` were saved as context. Text in them addressed to AI agents was treated as data, not as instructions. | Instruction-source hygiene. |
